# Requirements

## Overview

View Market Analysis lets users select a supported trading symbol and inspect the deterministic market analysis generated by the analysis engine for that symbol: regime assessment, risk assessment, economic assessment, exposure profile, and catalog recommendation. The UI presents loading and error states while retrieving data.

## Goals

- Enable users to inspect backend market analysis for a chosen symbol without leaving the product UI.
- Surface regime, risk, economic, exposure, and recommendation outputs in a clear, data-first layout.
- Communicate fetch progress and failures with recoverable error handling.
- Use canonical Market Data terminology and shared design-system wording.
- Replace any Analysis destination stub with the full analysis product view inside the shared application layout.

## Functional Requirements

```text
REQ-001

WHEN the user opens the market analysis view, THE SYSTEM SHALL present a control that allows the user to select one symbol from the set of supported trading symbols.
```

```text
REQ-002

WHEN the user selects a supported trading symbol, THE SYSTEM SHALL retrieve market analysis for that symbol from GET /markets/{symbol}/analysis.
```

```text
REQ-003

WHEN market analysis for the selected symbol has been retrieved successfully, THE SYSTEM SHALL display the regime assessment.
```

```text
REQ-004

WHEN market analysis for the selected symbol has been retrieved successfully, THE SYSTEM SHALL display the risk assessment.
```

```text
REQ-005

WHEN market analysis for the selected symbol has been retrieved successfully, THE SYSTEM SHALL display the economic assessment.
```

```text
REQ-006

WHEN market analysis for the selected symbol has been retrieved successfully, THE SYSTEM SHALL display the exposure profile.
```

```text
REQ-007

WHEN market analysis for the selected symbol has been retrieved successfully, THE SYSTEM SHALL display the catalog recommendation.
```

```text
REQ-008

WHILE a market analysis request for the selected symbol is in progress, THE SYSTEM SHALL present a loading state to the user.
```

```text
REQ-009

IF the market analysis request for the selected symbol fails, THEN THE SYSTEM SHALL present an error state to the user.
```

```text
REQ-010

WHEN the market analysis view is showing an error state for a selected symbol, THE SYSTEM SHALL provide a recovery action that retries GET /markets/{symbol}/analysis for that symbol.
```

```text
REQ-011

WHEN no supported trading symbol is selected, THE SYSTEM SHALL not call GET /markets/{symbol}/analysis and SHALL present an empty state that prompts the user to select a symbol.
```

```text
REQ-012

THE SYSTEM SHALL present all user-facing labels and messages for this feature using locale catalog keys (design-system shared wording where applicable; feature-specific keys otherwise), and SHALL NOT hardcode user-facing English in components.
```

```text
REQ-013

WHEN the user navigates to the Analysis destination in the shared application layout, THE SYSTEM SHALL render this market analysis view as the Analysis product content (not a placeholder stub).
```

## Non-Functional Requirements

```text
NFR-001

THE SYSTEM SHALL implement this feature with React 19, TypeScript, and Vite, consistent with knowledge/architecture.md.
```

```text
NFR-002

THE SYSTEM SHALL consume shared UI primitives, tokens, and shared wording from @market-data/brand where applicable, and SHALL NOT fork brand tokens or rewrite shared design-system copy locally.
```

```text
NFR-003

THE SYSTEM SHALL use canonical product terminology from knowledge/writing/terminology.md for Symbol, Regime, Risk, Economic, Exposure, Recommendation, and Analysis in requirements-facing and user-facing language.
```

```text
NFR-004

User-facing copy for this feature SHALL follow knowledge/writing/writing-guidelines.md (precise, calm, formal, data-first; ellipsis character for loading; sentence-case labels).
```

```text
NFR-005

THE SYSTEM SHALL keep feature-specific locale strings in src/locales/en.json and read them via the application message helpers; shared chrome and domain labels SHALL prefer @market-data/brand/wording.
```

```text
NFR-006

When a matching export exists in @market-data/brand/ui, THE SYSTEM SHALL use that brand primitive for the corresponding UI need (Select, Skeleton, Alert, Button, Page, Stack, Text, SectionHeading, Badge, Card) and SHALL NOT substitute native HTML controls for those roles.
```

## Acceptance Criteria

- [ ] The user can select a supported trading symbol.
- [ ] The UI retrieves data from GET /markets/{symbol}/analysis for the selected symbol.
- [ ] The regime assessment is displayed after a successful response.
- [ ] The risk assessment is displayed after a successful response.
- [ ] The economic assessment is displayed after a successful response.
- [ ] The exposure profile is displayed after a successful response.
- [ ] The catalog recommendation is displayed after a successful response.
- [ ] A loading state is presented while the request is in progress.
- [ ] An error state is presented when the request fails, with a retry action available.
- [ ] No analysis request is made until a symbol is selected; an empty state prompts selection.
- [ ] The Analysis layout destination renders this feature view (not a stub).
- [ ] User-facing strings come from locale catalogs / brand wording, not hardcoded English in components.
